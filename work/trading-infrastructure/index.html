01 · The challenge

Fresh data under pressure.

Trading systems are unforgiving: stale data, slow APIs or inconsistent exchange state immediately degrade the product. The platform needed to coordinate high-volume API traffic and realtime market updates while keeping user-facing workflows responsive.

HOT PATH

Optimize what users feel

Critical request paths needed to stay fast under load instead of being treated like ordinary CRUD traffic.

CACHE

Reduce repeated work

Redis helped keep frequently accessed state close to the application and reduce backend pressure.

REALTIME

Push state, don’t poll it

WebSockets kept market and order state synchronized without relying on expensive repeated requests.

02 · Engineering work

Design around the hot path.

  • Built realtime WebSocket workflows for synchronized market and order updates.
  • Used Redis caching to reduce repeated work and improve response times.
  • Designed APIs and service boundaries around high-throughput trading workflows.
  • Contributed to architecture capable of handling 10,000+ API requests per minute.
  • Worked on sub-100ms response paths where latency materially affected experience.
  • Applied reusable packages and shared engineering patterns across product areas.
03 · Outcome

Performance that users can feel.

The broader platform work contributed to a 40% reduction in server latency while supporting high-throughput realtime behavior. Just as importantly, the work strengthened reusable engineering patterns around services, caching and production delivery.

The lesson: latency is not only a backend metric. In realtime products it is part of trust, feedback and the overall user experience.
